# План спринтов — PersonalCRM

> Черновик. Спринты ~2 недели. Приоритеты и объём уточняем перед стартом каждого.

## Sprint 2 — MVP синхронизации

**Цель:** подтянуть контакты из Outlook и из файла, без дублей. (Раздел "MVP" в архитектуре.)

- [x] OAuth-флоу с Microsoft (connect + callback, хранение зашифрованных токенов) — *код готов, нужны реальные креды Azure для end-to-end*
- [x] Pull контактов через Microsoft Graph (`fetch_outlook_contacts`)
- [x] Маппинг Outlook → модель CRM (`map_outlook_to_crm`)
- [x] Дедупликация по телефону/email (автоматический merge ≥ 90)
- [x] Импорт файла CSV/vCard/Telegram: upload → preview (с дублями) → confirm
- [x] Кнопка «Синхронизировать» (ручной trigger) + sync_log
- [x] UI разрешения дублей (выбор merge/skip/create для score 70–89)

**Definition of Done:** подключаю Outlook, жму «Синхронизировать» — контакты появляются без дублей; загружаю CSV — вижу превью и подтверждаю.

> Статус: импорт + дедуп проверены live и юнит-тестами. Microsoft OAuth/Graph покрыт тестами с мок-Graph; для боевой проверки нужно зарегистрировать приложение в Azure AD (MS_CLIENT_ID/SECRET/REDIRECT_URI). Telegram-парсер уже сделан здесь (в плане Sprint 3 был — закрыт раньше).

## Sprint 3 — Полноценный sync

**Цель:** real-time, двусторонний, Google. (Раздел "v2" в архитектуре.)

- [x] Google People API: OAuth + pull + маппинг (`sync/google.py`)
- [x] Delta sync (Microsoft) + sync tokens (Google, 410-resync)
- [x] Webhooks Microsoft (subscription create/renew/delete + публичный обработчик)
- [x] Двусторонний push (CRM → Outlook/Google) + сохранение external_id
- [x] Разрешение конфликтов — **last-write-wins** через `merge_contacts` (UI-выбор отложен, см. QUESTIONS)
- [x] Импорт Telegram export (JSON) — *сделано в Sprint 2*
- [x] Фоновый scheduler (APScheduler: periodic sync 30м, refresh токенов 15м, продление вебхуков 12ч)

**Definition of Done:** изменение в Outlook прилетает в CRM почти мгновенно; правка в CRM уходит обратно; Google подключается и синкается.

> Статус: весь код + 113 тестов (мок-Graph/People). **Боевая проверка OAuth/webhooks требует реальных кредов (Azure, Google Cloud) и публичного HTTPS-домена** — webhooks на localhost не приходят. UI: кнопки «Подключить Outlook/Google», ручной sync, история. Push и подписки пока только через API (UI-кнопки — Sprint 4 или по запросу).

## Sprint 4 — Self-hosting и боевой sync

**Цель:** вся система крутится на своей машине и доступна снаружи по HTTPS; Outlook и Google работают вживую.

- [ ] `docker-compose` для прод-режима на своей машине (MongoDB, backend, frontend), автозапуск
- [ ] Cloudflare Tunnel (или аналог) → публичный HTTPS-домен, `PUBLIC_BASE_URL`
- [ ] Реальные секреты вместо dev-дефолтов (`SECRET_KEY`, пароль, ключ Fernet)
- [ ] Резервные копии MongoDB **вне машины** + проверка восстановления
- [ ] Регистрация приложений в Azure AD и Google Cloud, боевая проверка OAuth, pull/push, вебхуков
- [ ] Простой мониторинг (health-check снаружи, уведомление, если машина недоступна)

**Definition of Done:** с телефона по HTTPS открываю CRM; подключаю Outlook и Google — контакты приходят, правка в Outlook прилетает через вебхук.

## Sprint 5 — Карточки и вопросы к человеку

**Цель:** гибкая карточка без «душности» и отдельный учёт вопросов/ответов.

- [ ] Шаблоны карточек («Клиент», «Друг», «Инвестор»…) с набором полей по умолчанию
- [ ] Типизированные custom fields (текст, дата, число, список, ссылка) вместо свободного словаря
- [ ] Сущность `Question` (контакт, текст, статус open/answered/dropped, ответ, источник, `ask_at`)
- [ ] UI: вопросы в карточке, быстрое добавление/закрытие
- [ ] Главный экран — одна строка ввода (поиск + переход в карточку в один клик)

**Definition of Done:** создаю контакт по шаблону, добавляю своё поле и вопрос «как зовут дочь?», потом закрываю его ответом.

## Sprint 6 — Локальный ИИ (Qwen)

**Цель:** «один раз заполнил — дальше говорю с ИИ», модель — своя.

- [ ] Интерфейс `LLMProvider` (OpenAI-совместимый API), по умолчанию — локальный Qwen; запасной вариант (Claude API) выключен по умолчанию
- [ ] Слой инструментов поверх CRM: `search_contacts`, `get_contact`, `update_fields`, `add_note`, `add_question`, `answer_question`, `create_task`
- [ ] Быстрый захват: свободный текст → JSON по схеме (structured output) → предпросмотр изменений → применить
- [ ] Строка «спроси»: вопросы по базе на естественном языке
- [ ] Голос: распознавание речи локально (faster-whisper)
- [ ] Набор тестовых примеров (eval) для сравнения моделей и промптов

**Definition of Done:** диктую «встретил Петю, дочке 5 лет, переезжает в Дубай» — вижу предпросмотр (поле, закрытый вопрос, заметку) и применяю в один клик.

## Принятые решения

- **Бэкенд:** FastAPI + MongoDB (как в архитектуре)
- **Фронтенд:** Next.js (React) — с прицелом на масштабирование (SSR, роутинг, API routes)
- **Режим:** single-user (multi-user — на будущее, в модель данных не закладываем)
- **Хостинг:** своя машина + Cloudflare Tunnel для HTTPS (вместо Timeweb, решено в 10.2026)
- **ИИ:** локальный Qwen на своей машине; Claude API — только запасной вариант; MCP — Sprint 8

- Next.js: App Router или Pages Router? Что для запросов к API (React Query / SWR)?

**Definition of Done:** подключаю Outlook, жму «Синхронизировать» — контакты появляются без дублей; загружаю CSV — вижу превью и подтверждаю.

## Sprint 3 — Полноценный sync

**Цель:** real-time, двусторонний, Google. (Раздел "v2" в архитектуре.)

- [x] Импорт Telegram export (JSON) — *сделано в Sprint 2*
- [x] Фоновый scheduler (APScheduler: periodic sync 30м, refresh токенов 15м, продление вебхуков 12ч)

**Definition of Done:** изменение в Outlook прилетает в CRM почти мгновенно; правка в CRM уходит обратно; Google подключается и синкается.

> Статус: весь код + 113 тестов (мок-Graph/People). **Боевая проверка OAuth/webhooks требует реальных кредов (Azure, Google Cloud) и публичного HTTPS-домена** — webhooks на localhost не приходят. UI: кнопки «Подключить Outlook/Google», ручной sync, история. Push и подписки пока только через API (UI-кнопки — Sprint 4 или по запросу).

## Принятые решения

- **Бэкенд:** FastAPI + MongoDB (как в архитектуре)
- **Фронтенд:** Next.js (React) — с прицелом на масштабирование (SSR, роутинг, API routes)
- **Режим:** несколько пользователей с открытой регистрацией (с 10.2026, к тестированию на 1–10 людях). Изоляция — отдельная база MongoDB на пользователя, поэтому в модели данных нет поля владельца; рейт-лимиты на все запросы (Redis). Очередь задач ИИ — Redis + arq (Kafka избыточна для такого масштаба), вложения — MinIO (S3) на сервере
- **Хостинг:** сначала рабочий ПК (Sprint 4–7), затем своя машина-сервер + Cloudflare Tunnel для HTTPS (Sprint 8); Timeweb отменён (10.2026)
- **ИИ:** локальный Qwen; пока работаем на ПК — Qwen-сервер по локальной сети или маленькая модель через Ollama; Claude API — только запасной вариант; MCP — Sprint 9

## ИИ-помощник 2.0 (W1-6): чаты, графики, аналитика, досье

Сделано:
- **Чаты** (`chats`, `chat_messages` в базе пользователя): список, создание, переименование, удаление, история с пагинацией — `/api/assistant/chats`. Название — из первого сообщения. Сообщение → задача `chat` в очереди; `/ask` и `/capture` работают как раньше.
- **Контекст:** сводка старых сообщений (`chat.summary`, `summary_upto` — сколько первых сообщений она покрывает) + последние `CHAT_CONTEXT_MESSAGES` (12). Сводка пересчитывается пачками по `CHAT_SUMMARY_BATCH` сообщений.
- **Выбор пути** правилами (`ai/chat.py: route_message`): запись → быстрый захват (блок `capture_preview`, применение через `/jobs/{id}/apply`), вопрос или просьба показать цифры → «план → выполнение → вывод» (до 3 инструментов, параметры проверяются строго, цифры графиков и таблиц берутся из базы, не от модели).
- **Инструменты аналитики** (`ai/analytics.py`, реестр `ANALYTICS_TOOLS` — пригодится MCP-серверу): `count_contacts_by`, `interactions_over_time`, `birthdays_by_month`, `contacts_added_over_time`, `top_contacts_by_interactions`, `stale_contacts`. Коллекции `interactions` и `groups` читаются защитно: без них ряды пустые.
- **Блоки** ответа: `text`, `chart` (bar/line/pie, ≤100 точек), `table` (≤200 строк), `contacts`, `capture_preview`.
- **Досье контакта:** `POST/GET /api/assistant/dossier/{contact_id}` (задача `dossier`, результат в коллекции `dossiers`), клиент — `lib/api-assistant.ts`.
- **Фронтенд:** страница помощника — чат с панелью чатов справа, блоки в `components/assistant/blocks/` (recharts).
- **Оценка:** в `backend/evals` добавлены случаи `kind: tools` — выбор инструмента на типичных вопросах.

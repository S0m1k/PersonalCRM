# Контакты и календарь CRM в телефоне (iPhone / Android)

CRM работает как **CardDAV-сервер** (адресные книги) и **CalDAV-сервер** (календари) — это стандарты, которые iPhone понимает без приложений, а Android — через бесплатное приложение DAVx⁵. Логин и пароль для телефона один на оба.

Что получится:
- в «Контактах» и «Звонилке» телефона появится адресная книга **PersonalCRM** со всеми контактами CRM;
- новый контакт или правка на телефоне сразу попадает в CRM, правка в CRM — на телефон (при следующей синхронизации, обычно в течение нескольких минут);
- удалённый на телефоне контакт уходит в корзину базы (`contacts_trash`), а не пропадает насовсем;
- поля, которых нет в телефоне (шаблон, свои поля, вопросы, приоритет), правки с телефона не трогают;
- в «Календаре» телефона появится календарь **PersonalCRM** со всеми событиями CRM: встреча, созданная на телефоне, попадает в CRM и обратно, а привязка встречи к людям и «вопросы на встрече» остаются в CRM;
- повторяющиеся встречи, напоминания и часовые пояса, созданные на телефоне, сохраняются как есть. В самой CRM такая встреча показывается один раз — на дате начала;
- события, пришедшие из Outlook или Google, на телефоне **только читаются** (правка или удаление с телефона отклоняются): их записью у провайдера занимается CRM, где есть проверка прав. Правьте такие события в CRM;
- удалённое на телефоне событие уходит в корзину базы (`events_trash`).

> **Внимание к дублям.** Если на телефоне уже синхронизированы Outlook или Google, те же люди будут и в их адресных книгах, и в PersonalCRM, а события — и в календаре Outlook/Google, и в PersonalCRM. Решение — в «Контактах» и «Календаре» (iPhone: «Списки» / «Календари», Android: фильтр учётных записей) оставить на виду только PersonalCRM: в CRM и так собраны контакты и события из Outlook и Google.

## 1. Подготовить компьютер (пока CRM работает на этом ПК)

Телефон должен достучаться до компьютера по домашней Wi-Fi сети.

1. Пароль для телефона выпускается в CRM: **Аккаунт → Телефон → «Выпустить пароль для телефона»**. Он показывается один раз —
   введите его в телефоне сразу. Логин — ваш email (у первого пользователя — `admin`). Новый пароль отменяет старый.
2. Разрешить доступ к backend из домашней сети. Создайте в корне проекта файл `.env` (рядом с `docker-compose.yml`) со строкой:

   ```
   BACKEND_BIND=0.0.0.0
   ```

   и перезапустите:

   ```bash
   docker compose up -d backend
   ```

3. Разрешить порт 8000 в брандмауэре Windows (PowerShell от администратора):

   ```powershell
   New-NetFirewallRule -DisplayName "PersonalCRM CardDAV" -Direction Inbound -Protocol TCP -LocalPort 8000 -Profile Private -Action Allow
   ```

   `-Profile Private` — только для домашней (частной) сети, в кафе и т. п. порт будет закрыт.

4. Узнать IP компьютера: `ipconfig` → «IPv4-адрес» у Wi-Fi адаптера, например `192.168.1.10`.

> **Безопасность.** Пока нет HTTPS (появится при переезде на сервер, Sprint 8), пароль CardDAV передаётся по Wi-Fi открыто. В домашней сети это приемлемо, в общественной — нет. Поэтому отдельный пароль для телефона, а не пароль входа в CRM.

## 2. iPhone

1. **Настройки → Приложения → Контакты → Учётные записи → Новая учётная запись → Другое → Учётная запись CardDAV.**
2. Сервер: `192.168.1.10:8000` (ваш IP) или адрес сервера CRM, Пользователь: ваш email, Пароль: пароль для телефона из шага 1.1, Описание: `PersonalCRM`.
3. Если iPhone пишет, что не может подключиться по SSL — согласитесь продолжить без SSL, затем в учётной записи: **Дополнительно → «Использовать SSL» выкл., порт 8000.**
4. Откройте «Контакты» → «Списки» — появится PersonalCRM.
5. **Календарь:** Настройки → Приложения → **Календарь** → Учётные записи → Новая учётная запись → Другое → **Учётная запись CalDAV**. Сервер, пользователь и пароль — те же, Описание: `PersonalCRM`. Календарь «PersonalCRM» появится в списке «Календари»; при создании встречи выберите его.

## 3. Android

На Android обычно уже работает аккаунт Google, а он синхронизируется с CRM через «Синхронизацию → Google». CardDAV нужен, если контакты хранятся только в телефоне или нужен отдельный список PersonalCRM.

1. Установите **DAVx⁵** (бесплатно в F-Droid, платно в Google Play).
2. «+» → **Вход по URL и имени пользователя**:
   - URL: `http://192.168.1.10:8000/dav/`
   - Пользователь: ваш email, Пароль: пароль для телефона из шага 1.1
3. DAVx⁵ найдёт и адресную книгу, и календарь **PersonalCRM** — отметьте оба и включите синхронизацию. Интервал — в настройках аккаунта DAVx⁵ (например, 15 минут).

## Проверка с компьютера

```bash
curl -u EMAIL:ПАРОЛЬ_ДЛЯ_ТЕЛЕФОНА -X PROPFIND -H "Depth: 1" http://localhost:8000/dav/addressbooks/contacts/
```

Ответ `207 Multi-Status` со списком карточек — сервер работает. Календарь проверяется так же:

```bash
curl -u EMAIL:ПАРОЛЬ_ДЛЯ_ТЕЛЕФОНА -X PROPFIND -H "Depth: 1" http://localhost:8000/dav/calendars/events/
```

## Если не подключается

| Что видно | Причина и решение |
|---|---|
| Телефон долго думает и пишет «не удаётся проверить» | Не открыт порт: шаги 1.2 и 1.3; телефон и ПК в одной Wi-Fi сети? |
| «Неверный пароль» | Логин — email, пароль — выпущенный для телефона, а не пароль входа в CRM. Выпустили новый — старый больше не работает |
| iPhone раз за разом просит пароль, а в логах сервера нет заголовка Authorization | iOS не отправляет пароль по HTTP — подключайтесь по HTTPS-адресу сервера |
| Событие не меняется на телефоне, выдаёт ошибку | Это событие из Outlook или Google — с телефона оно только читается. Правьте его в CRM (там изменение уйдёт и к провайдеру) |
| Встреча удалилась случайно | Она в коллекции `events_trash` в MongoDB (`event_id` — прежний идентификатор) — можно вернуть |
| Контакт удалился случайно | Он в коллекции `contacts_trash` в MongoDB — можно вернуть. Его файлы не удаляются: вернутся вместе с контактом, если восстановить его с тем же `_id` (`contact_id` в корзине), а до тех пор занимают место в квоте |

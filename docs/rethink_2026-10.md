# PersonalCRM — пересмотр концепции (октябрь 2026)

> Цель: менеджер контактов гибче Outlook / Google Контактов / заметок, проще Notion, с ИИ.
> Принцип: **минимум кликов до информации. Один раз заполнил — дальше говоришь с ИИ.**

---

## 1. Сводка: конкуренты + чат ChatGPT

### Что сказано в чате ChatGPT («Примеры bootstrap компаний», 11.10)
- Рынок делится на **Personal CRM** (друзья, нетворкинг) и **Relationship CRM для профессионалов**. Вторую проще монетизировать: ценность легче перевести в деньги.
- Примеры: Monica (open source, bootstrap), Dex (больше 30 тыс. пользователей), Clay (куплен Automattic в 2025, привлёк венчурные деньги), folk (ушёл в B2B для команд).
- Модельный расчёт: 1 500 ₽/мес при марже 50% → нужно около 5,5 тыс. платящих, чтобы получать 50 млн ₽ прибыли в год. **Главная сложность — найти людей, готовых годами платить, а не разработка.**
- Гипотеза ChatGPT: не очередная универсальная CRM, а **AI Relationship Manager** для предпринимателей и руководителей. Он помнит контекст и договорённости, напоминает, с кем давно не общались, и подсказывает, кто из твоей сети поможет с задачей.
- Открытый вопрос из чата: какой сегмент выбрать — массовый ($5–10), предприниматели ($20–50) или премиум-ассистент ($100+).

### Конкуренты (состояние на 2026)

| Продукт | Сильное | Слабое (для нашей цели) | ИИ / MCP |
|---|---|---|---|
| **Mesh** (бывш. Clay, Automattic) | Сам собирает контакты из почты, календаря и соцсетей и обогащает их. Бесплатно до 1 000 контактов. С 08.2026 есть Android | Почти не даёт настраивать карточку. Данные в облаке | Nexus AI: поиск по сети на естественном языке (ранний доступ) |
| **Dex** | LinkedIn, уведомления о смене работы, расширение для браузера, напоминания | Нет бесплатного тарифа. Ориентирован на LinkedIn. Неудобно добавлять контакты вживую | **Есть официальный MCP-сервер** (11 инструментов) с подключением к Claude, только на тарифе Professional |
| **folk** | Гибкие поля, пайплайны, работа в команде | Это уже лёгкая CRM для продаж; для одного человека тяжеловато. $24 за пользователя в месяц | Хостинговый MCP (`mcp.folk.app`). Есть сомнения, что он полностью работает |
| **Covve** | Мобильное приложение, сканирование визиток, ISO 27001 | Мало гибкости, слабые интеграции | Минимально |
| **Monica** | Open source, можно развернуть у себя, есть поля «что обсуждали», «долги», «подарки» | Нет синхронизации с почтой и календарём, нет мобильного приложения, всё вводится вручную. Версия v3 переписывается с нуля | Нет |
| **Attio / HubSpot** | Мощные MCP-серверы (запись в CRM с подтверждением) | Это B2B для продаж, для личных контактов слишком тяжело | MCP есть |
| **Notion** | Любая структура | «Душный»: схему базы строишь сам, медленный ввод с телефона, нет синхронизации контактов | Notion AI внутри, MCP есть |

### Выводы — где свободная ниша
1. **Ни у кого нет связки «вопросы к человеку ↔ ответы ↔ встреча в календаре».** Максимум — заметки и напоминания «связаться». Это наше отличие.
2. Ниша **«ИИ поверх своих данных»** только начинает занимать: Dex и folk уже сделали MCP, но платно и с упором на LinkedIn или продажи. Никто не делает упор на **ввод голосом или свободным текстом → структурированная карточка**.
3. Слабое место почти всех — **настраиваемые поля без создания схем, как в Notion**. Решение: готовые шаблоны карточек («Клиент», «Друг», «Инвестор»…) плюс свободные поля, которые ИИ добавляет сам.
4. **Нативные контакты телефона** у всех работают через Google или iCloud. Ход, который обычно упускают: собственный **CardDAV-сервер**. Тогда iPhone и Android подключают CRM как обычный аккаунт контактов, и звонилка видит наши карточки без отдельного приложения.
5. Рынок (по чату и конкурентам): пока проект single-user — это «инструмент для себя». Если когда-нибудь станет продуктом, ставка на сегмент «предприниматели и руководители», а не на массовый.

## 2. Обязательные составляющие (что есть / чего нет)

| Требование | Статус в коде | Что сделать |
|---|---|---|
| Интеграция с Outlook (Graph) | ✅ pull/push, delta, вебхуки (на моках, нужны креды Azure и HTTPS-домен) | Боевая проверка |
| Интеграция с Google (People API) | ✅ pull/push, syncToken (на моках) | Боевая проверка |
| Нативные контакты (iOS/Android) | ❌ (есть только импорт vCard/CSV) | **CardDAV-эндпоинт** в бэкенде (двусторонний: телефон ↔ CRM) |
| Карточки с настраиваемыми полями | 🟡 есть `custom_fields`, но без схемы и типов | Шаблоны карточек + типизированные поля (текст, дата, список, ссылка) + поля, которые создаёт ИИ |
| **Вопросы к человеку и ответы** | ❌ | Новая сущность `Question` (см. ниже) |
| Календарь и задачи | ❌ (скоупы в архитектуре упомянуты, кода нет) | Graph Calendar / To Do + Google Calendar / Tasks; задачи и события, привязанные к контакту |

### Модель «Вопросы ↔ ответы» (предложение)
```
Question {
  contact_id, text, status: open | answered | dropped,
  answer?, answered_at?, source: manual | ai | meeting,
  ask_at?: "next_meeting" | date,   # когда напомнить
  tags[]
}
```
- Перед встречей (событие в календаре, где этот контакт среди участников) открытые вопросы автоматически показываются в описании события и в push-уведомлении.
- После встречи диктуешь ИИ «Он сказал, что переезжает в Дубай, дочке 5 лет». ИИ закрывает подходящие вопросы и заполняет поля карточки.

## 3. Варианты архитектуры ИИ

Общее для всех вариантов: **один слой «инструментов»** поверх API CRM — `search_contacts`, `get_contact`, `update_fields`, `add_note`, `add_question`, `answer_question`, `create_task`, `schedule_meeting`. Пишем его один раз, а подключать можно к любому варианту ниже.

### A. MCP-сервер для Claude и ChatGPT
Наш бэкенд отдаёт удалённый MCP-сервер (Streamable HTTP + OAuth). Пользователь подключает его как коннектор в Claude (веб, десктоп, мобильное приложение) и в ChatGPT (Apps/коннекторы).
- ➕ **Мы не платим за токены**: ИИ — подписка пользователя.
- ➕ Лучшие модели, голосовой режим и мобильные приложения Claude/ChatGPT бесплатно. Цель «говорю с ИИ» достигается почти без своего UI.
- ➕ Быстро сделать: тонкая обёртка над готовым REST API. Так уже работают Dex и folk.
- ➖ Нужен публичный HTTPS и OAuth 2.1 (та же блокировка, что и для вебхуков: домен на Timeweb).
- ➖ Внутри нашего приложения ИИ нет. Нет проактивности: ИИ ничего не делает, пока ты сам его не спросишь.
- ➖ Данные контактов уходят провайдеру ИИ. Поведение клиента (подтверждения, лимиты) от нас не зависит.

### B. Собственная локальная LLM (Ollama / llama.cpp: Qwen, Llama, Gemma ~8–32B)
- ➕ Полная приватность, нет оплаты за токены, работает офлайн.
- ➖ Небольшие модели заметно хуже с вызовом инструментов и с русским языком, особенно при разборе свободного текста в поля.
- ➖ Нужно железо: GPU или мощный Mac. На телефоне и на дешёвом VPS не работает.
- ➖ Поддержка, обновления моделей и оценка качества — твоя забота.

### C. Свой сервер со своей моделью (GPU в облаке)
- ➕ Контроль, данные не уходят третьим лицам, возможен дообучение.
- ➖ **Дорого**: аренда GPU стоит сотни долларов в месяц и больше, даже когда нагрузки нет.
- ➖ Качество всё равно ниже передовых моделей. Много DevOps.
- ➖ Для одного пользователя экономически бессмысленно. Имеет смысл только при тысячах пользователей или жёстких требованиях комплаенса.

### D. Claude по API из нашего бэкенда (у нас — запасной вариант)
- ➕ Лучшее качество разбора свободного текста и голоса в структуру. ИИ **внутри нашего UI**: одна строка ввода, быстрый захват, подсказки, проактивность (фоновые задачи: «давно не общались», «вопросы перед встречей»).
- ➕ Полный контроль над промптами, инструментами и подтверждениями. Prompt caching и недорогие модели (Haiku) для простых задач.
- ➖ Оплата за использование: для одного человека это единицы долларов в месяц, при росте нужен бюджет.
- ➖ Нужен ключ и секрет. Данные уходят в Anthropic (по API они по умолчанию не используются для обучения).
- ➖ Свой чат и голосовой UI делаем сами.

### Решение (обновлено): всё у нас, основа — свой Qwen
У пользователя уже есть своя машина, работающая как сервер с Qwen. Поэтому главный минус варианта B (железо) снят: машина уже есть и за неё уже заплачено.

**Основа — B: локальный Qwen внутри приложения. Затем A (MCP). D (Claude API) — только запасной вариант. C не делаем.**

Почему этого достаточно: наши задачи для ИИ несложные.
- **Разбор текста в карточку.** Это извлечение данных по схеме. JSON-ответ жёстко ограничивается схемой средствами сервера модели: structured outputs в Ollama, grammar в llama.cpp или guided decoding в vLLM.
- **Вызов инструментов.** Набор маленький (около 8 штук), без длинных цепочек рассуждений.
- **Вопросы по базе.** Контактов сотни, может тысячи. Сначала обычный поиск (текстовый плюс, позже, эмбеддинги), модель только формулирует запрос и ответ.

Как устроено:
1. **Вся система на своей машине:** MongoDB, FastAPI, Next.js, Qwen, распознавание голоса (faster-whisper) — одним `docker-compose`.
2. **Доступ снаружи через Cloudflare Tunnel** (или аналог): HTTPS-домен без белого IP и без проброса портов. Это снимает главный блокер — OAuth и вебхуки Outlook/Google, а позже и MCP.
3. **Провайдер LLM за интерфейсом** `LLMProvider` (OpenAI-совместимый API). По умолчанию — локальный Qwen. Запасной вариант (Claude API) включается настройкой, по умолчанию выключен: данные не покидают машину.
4. **MCP — вторым этапом** поверх того же слоя инструментов: доступ к контактам голосом из приложений Claude и ChatGPT на телефоне.

Риски:
- **Доступность.** Всё работает, только пока машина включена и есть интернет. Нужен автозапуск, мониторинг и **резервные копии MongoDB вне машины**.
- **Качество модели зависит от её размера.** Модель меньше ~14B может ошибаться в полях. Нужен небольшой набор тестовых примеров для проверки (eval), чтобы сравнивать модели и промпты.
- ❓ **Нужно уточнить:** версия и размер Qwen, объём видеопамяти, ОС машины, через что запущена модель (Ollama, vLLM, LM Studio…).
